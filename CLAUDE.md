# BestShots — техническое описание для разработчика (и для Claude Code)

Локальная программа (Python, Windows, офлайн) для разбора фотоархива: сканирование → оценка кадров → отбор в интерфейсе → экспорт копий → обучение на выборе пользователя; отдельно — поиск дубликатов с карантином. Исходные фото только читаются; экспорт только копирует (`shutil.copy2`); дубли перемещаются в карантин `_Дубли` (никогда не удаляются).

## Запуск

- Обычно: `BestShots.exe` (собирается `install.bat`) запускает `review.py` через `.venv\Scripts\pythonw.exe` и открывает окно pywebview; без pywebview — браузер.
- Без exe: `.\.venv\Scripts\python review.py` (`--db`, `--out`, `--port 8765`, `--no-browser`).
- Консоль: `scan.py <папка>`, `analyze.py [--force|--limit N|--score-only|--keep-decided]`, `train.py [--seed-labels]`, `dupes_scan.py <папка>`.
- Установка/сборка: `install.bat` → `install.ps1` (`-DryRun`, `-SkipDeps`, `-SkipExe`). Ручная сборка exe: `python -m PyInstaller --onefile --noconsole --name BestShots --icon icon.ico launcher.py`.

## База `bestshots.db` (SQLite)

- `files` — файл, дата и её источник, размер, mtime, sha256, разрешение, orientation, камера, экспозиция, `event_id`, `series_id`.
- `analysis` (ключ `path`) — метрики и эмбеддинг: резкость, свет, лица, `aesthetic`, `topiq_iaa`, `topiq_nr`, `embedding`.
- `scores` — `group_id`, `emotion`, `clip_emotion`, `score`, `base_score`, `personal`, `reject`, `reject_reason`, `selected` (рекомендация системы).
- `decisions(path, keep, decided_at)` — решения пользователя (колонка `print` устарела). Итог = `decisions`, иначе `scores.selected`. Анализ решения не затирает.
- `event_reviews`, `event_exports`, `labels` — отметки «проверено», экспортированные события, метки для обучения.
- Папки: `roots`, `folder_status`, `folder_cache`, `excluded`. Дубли: `dup_files`, `dup_groups`, `dup_members`, `dup_checked`, `dup_prio`, `dup_moves`.

## Как считается рекомендация

1. Брак — жёсткий фильтр: смаз, тёмный, пересвет, `topiq_nr` < `TECH_NR_MIN`. Брак не рекомендуется никогда, вручную отобрать можно.
2. Группы похожих — внутри события, косинус CLIP ≥ `SIM_THRESHOLD` и интервал ≤ `GROUP_MAX_GAP_S`; сравнение только с соседями по времени (без матрицы N×N). Группа «с лицами», если лица найдены хотя бы в одном кадре.
3. Базовый балл = `W_LAION`·LAION + `W_TOPIQ_IAA`·IAA + `W_TOPIQ_NR`·NR + `W_EMOTION`·эмоции (без лиц `W_EMOTION_NO_FACES`, остальные веса масштабируются). Улыбка — только бонус, штрафуется моргание.
4. Личная модель (если включена): итог = (1 − w)·базовый + w·вероятность, w = n / (n + `PERSONAL_K`).
5. Отбор в событии: лучший кадр группы с повторами — всегда; остальные места (одиночные и «разнообразные» кадры, до 3 на группу) — по баллу до цели `TARGET_SELECT_FRACTION`.

## Правила работы с данными

- Экспорт и обучение используют **только события, отмеченные «Проверено»** (`REVIEWED_SQL`); «Копировать и непроверенные…» — отдельная кнопка с подтверждением. `event_exports` и `labels` пишутся только для проверенных событий.
- Решения пользователя (`decisions`) не терять и не менять; операции над данными — с резервной копией базы.
- Экспорт раскладывает файлы только по годам: `ГГГГ\имя_файла`; уже экспортированный файл (в том числе в подпапках прежней раскладки) повторно не копируется; коллизии имён — суффикс `_2`.
- Карантин `<корень>\_Дубли` сохраняет структуру подпапок, пишется в `excluded`; решения и метки перемещённых файлов копируются на оригинал, если у него их нет.

## Интерфейс

- Панель «Папки» (статусы серый/синий/жёлтый/зелёный ✓/оранжевая точка, фильтр, контекстное меню, исключение), вкладки «Дубли» и «Отбор», S/M/L, части события (`REVIEW_PART_SIZE`), порции анализа (`ANALYZE_PART_CHOICES`, «подряд до конца»), окно ⚙.
- У каждой кнопки есть подсказка `title`. Параметры адреса для документации и тестов: `?tab=dupes|select`, `?size=S|M|L`, `?settings=1`.
- Настройки интерфейса (главная папка, раскрытые узлы, ширины панелей) — в `settings.json`.

## Дубли: пороги

`DUP_*` в `config.py` подобраны калибровкой на копиях (1280/640 px, q50, поворот) и на сериях: пересохранённые копии — pHash ≤ 2, dHash ≤ 8, корреляция 16×16 ≥ 0.9993; серийные кадры — корреляция ≤ 0.988. CLIP — подтверждение (≥ 0.90; для повёрнутой копии по повёрнутому кадру). Сравнение хэшей — `numpy.bitwise_count` (нужен numpy ≥ 2).

## Тестирование и осторожность

- Переменная окружения `BESTSHOTS_SETTINGS` подменяет `settings.json`. Тесты запускать на копии БД, на другом порту (не 8765), с отдельной папкой экспорта: API `/api/roots/set`, `/api/ui-state` пишут в настройки.
- `review.py` не стартует, если порт занят (без повторного использования порта).
- На ноутбуках с Modern Standby длинные задания замораживаются при погасшем экране: `power.py` запрашивает у Windows «выполнение необходимо» в каждом рабочем процессе; закрытая крышка при действии «Сон» всё равно усыпляет компьютер.

## Ограничения

- Метки кадров вне проверенных событий — рекомендации системы, а не выбор пользователя; поэтому обучение их не использует.
- Резкость и pyiqa считаются по превью 512 px; небольшая нерезкость на полном размере может не определиться.
- Отметка «проверено» привязана к номеру события; при пересчёте событий после добавления файлов номера могут сдвинуться.
- Видео в анализе не оцениваются; при поиске дублей — только точные копии. RAW сравниваются по встроенному JPEG-превью.
- Первый запуск на новой машине скачивает ≈ 3 ГБ моделей (нужен интернет); дальше офлайн. У части моделей (TOPIQ/pyiqa) лицензия только для некоммерческого использования — см. README.
