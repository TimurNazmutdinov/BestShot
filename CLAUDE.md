# BestShots — заметки о проекте и результаты работы

Локальная программа (Python, Windows, офлайн) для разбора семейного фотоархива: сканирование → оценка кадров → отбор в интерфейсе → экспорт копий → обучение на выборе пользователя. Исходные фото только читаются, экспорт только копирует (`shutil.copy2`).

Состояние на 2026-10-22. Тестовая папка: `C:\Projects\BestShots\Photo-samples` (166 JPG, Nikon D5100, 2019–2020, 945 МБ).

## Запуск

- Обычно: двойной клик по `BestShots.exe` (запускает `review.py` через `.venv\Scripts\pythonw.exe`, окно pywebview 1400×900; при недоступности pywebview — браузер).
- Без exe: `.\.venv\Scripts\python review.py` (`--db`, `--out`, `--port 8765`, `--no-browser`).
- Консольно: `scan.py <папка>`, `analyze.py [--force|--limit N|--score-only|--keep-decided]`, `train.py [--seed-labels]`.
- Пересборка exe: `.\.venv\Scripts\python -m PyInstaller --onefile --noconsole --name BestShots --icon icon.ico launcher.py`, exe скопировать в корень, `build/` и `dist/` удалить.

## База `bestshots.db` (SQLite)

- `files` — файл, дата и источник даты, размер, mtime, sha256, разрешение, orientation, камера, экспозиция/диафрагма/ISO/фокусное, `event_id`, `series_id`.
- `analysis` (ключ `path`) — метрики и эмбеддинг: резкость, свет, лица (`n_faces`, `smile`, `blink_frac`, `sharp_faces`, `face_method`), `aesthetic`, `topiq_iaa`, `topiq_nr`, `embedding`.
- `scores` — `group_id`, `group_size`, `emotion`, `clip_emotion`, `score` (итоговый), `base_score`, `personal`, `reject`, `reject_reason`, `selected` (рекомендация системы).
- `decisions(path, keep, print, decided_at)` — решения пользователя; `print` устарела. Итог = `decisions`, иначе `scores.selected`. Анализ решения не затирает.
- `event_reviews`, `labels(path, keep, at)`, `event_exports(event_id, at)` (события, из которых делался экспорт).
- Папки: `roots(path, added_at, last_scan)`, `folder_status(path, done, at)` (ручные отметки «отработана»), `folder_cache(path, direct_total, direct_new, accessible, has_dirs, scanned_at)` (кэш подсчёта на диске), `excluded(path, at)` (исключённые папки; `scan.py` их пропускает).

## Как считается рекомендация (сейчас)

1. Брак — жёсткий фильтр: смаз, тёмный, пересвет (`BRIGHT_FRAC_MAX` = 0.60), `topiq_nr` < `TECH_NR_MIN` (0.40). Брак не рекомендуется никогда, вручную отобрать можно.
2. Группы похожих: внутри события, косинус CLIP ≥ 0.92 и интервал ≤ 3 мин. Группа «с лицами», если лица найдены хотя бы в одном кадре.
3. Базовый балл = LAION 0.25 + topiq_iaa 0.25 + topiq_nr 0.15 + эмоции 0.35 (без лиц эмоции 0.15, остальные веса масштабируются). Улыбка — только бонус (`SMILE_BONUS`), штрафуется моргание.
4. Личная модель (если включена): итог = (1 − w)·базовый + w·вероятность, w = n / (n + 300).
5. Отбор в событии: лучший кадр группы с повторами — всегда; остальные места (одиночные и «разнообразные» кадры групп, до 3 на группу) — по баллу до цели `TARGET_SELECT_FRACTION` = 0.38.

## Результаты на Photo-samples

- 166 фото, 9 событий, 71 группа (36 с повторами), 32 серии; даты у всех из EXIF.
- Брак: 10 кадров (смаз 7, тёмный 4, качество 6 — причины пересекаются).
- Рекомендовано: 62–66 кадров, 37–38% (по событиям 36–40%).
- Лица (YuNet + MediaPipe): на DSC_0013–0016 по 2 лица, на DSC_0071–0074 по 6–7 (до правки находились 0–1).
- Личная модель, leave-one-event-out на 166 метках (при одинаковом числе рекомендаций): базовая угадала 30 из 66 (лишних 33), личная 34 из 66 (лишних 29). Включена, вес 0.36. Повторное обучение на копии: 33 против 30 из 68, не включена («не лучше предыдущей»).
- Скорость на CPU: полный анализ ~1,5–3 мин на 166 кадров; пересчёт только лиц ~55 с; pyiqa ~112 с; `--score-only` ~20 с (грузится текстовый кодировщик CLIP).
- Итоговый цикл через `BestShots.exe` на изолированной копии: выбор папки → анализ (166 кэшированы, 3 новых обработаны) → S/M/L → правка выбора → экспорт 68 файлов (393 МБ), повторный экспорт пропустил все → автообучение. Оригиналы не изменились (размер и mtime у всех 166).
- Размер проекта без Photo-samples (945 МБ) и Export (497 МБ): ~4,5 ГБ (models 2,6 ГБ, .venv 1,9 ГБ, остальное ~29 МБ).

## Панель «Папки» и экспорт по годам (2026-10-23)

- Слева над списком событий — мини-проводник главной папки (корень в `roots`, ключи интерфейса — в `settings.json`: `root`, `ui` — раскрытые узлы, выбранная папка, ширины/высоты, свёрнутость). Отдельный экран «Папка с фото» удалён.
- Статус папки: серый / синий (идёт анализ) / жёлтый («12 из 48») / зелёный ✓ + оранжевая точка (новые или изменённые файлы). «Отработана» = все проанализированные фото папки в событиях «проверено» или экспортированных, либо ручная отметка. Родитель зелёный, только если зелёные все его подпапки с фото. Расчёт — `folders.compute_stats` (кэш по счётчику версии `touch()`).
- Клик по папке фильтрует события и фото (`?folder=` / `view_folder`); события по-прежнему строятся по всей базе. Шапка: «Отработано: X из Y фото (Z%)».
- Меню папки: Анализировать, Отметить отработанной, Открыть в Проводнике, Исключить из анализа (удаляет из `files`/`analysis`/`scores`, но не из `decisions`/`labels`).
- Экспорт раскладывает файлы только по годам: `Export\ГГГГ\имя_файла`; файл, уже лежащий в папке года (в том числе в подпапках прежней раскладки `год\событие`), повторно не копируется; коллизии имён — суффикс `_2`.
- Подсказки (`title`) есть у каждой кнопки интерфейса, включая динамические (меню, диалоги).
- `scan.py`: удаление из `files` только внутри сканируемой папки (раньше сравнение шло по префиксу без разделителя), пропуск скрытых/системных/исключённых папок.
- Проверено на копиях: тестовая главная папка с подпапками (анализ → жёлтые → события одной подпапки проверены → зелёная, родитель «1 из 2» → новый файл → оранжевая точка, «Анализировать» обработал только его → исключение подпапки сохранило `decisions`/`labels`); копия реальной БД (корень определился сам); запуск через `BestShots.exe` на изолированной копии проекта.

## Вкладка «Дубли» (2026-10-23)

- Таблицы: `dup_files` (кэш хэшей по пути/размеру/mtime: sha256, pHash/dHash в 4 поворотах, `tiny` 16×16, emb), `dup_groups`/`dup_members` (`orig_manual`, `confirmed`, `uncertain`, `state` open/applied/ignored), `dup_checked`, `dup_prio`, `dup_moves` (журнал). Имена и пары RAW+JPEG считаются на лету по `dup_files`.
- Пороги в `config.py` (`DUP_*`) подобраны калибровкой: копии (1280/640 px, q50, поворот): pHash ≤ 2, dHash ≤ 8, корреляция 16×16 ≥ 0.9993; серийные кадры: корреляция ≤ 0.988, MAD ≥ 0.09 — на этом разделение; CLIP как подтверждение (≥ 0.90, для повёрнутой копии по повёрнутому кадру).
- Производительность: сравнение хэшей — `numpy.bitwise_count`, N=20 000 ≈ 10 с (≈ квадратично, 50 000 ≈ 1 мин); хэширование — пул процессов (1283 фото ≈ 10 с).
- Карантин `<корень>\_Дубли` (структура сохраняется), записывается в `excluded`; `scan.py`, `folders.py`, `dupes_scan.py` пропускают папку с именем `_Дубли`. Перемещение на том же диске — `os.replace`, иначе копия с проверкой размера и удаление исходного. Решения/метки перемещённых файлов копируются на оригинал, если у него их нет.
- Проверено на копиях: архив из Photo-samples (точные копии в другой подпапке, уменьшенные копии без EXIF, повёрнутая копия, DSC_0001 с другим содержимым, серия, RAW+JPEG, видео, битый файл, готовый `_Дубли`); перемещение, журнал, возврат, конфликт при возврате; запуск через `BestShots.exe`.

Сон в настройках был отключён, но Modern Standby (погасший экран/крышка) замораживает программы. Баллы считаются только в конце `analyze.py`, поэтому остановка раньше оставляла «Отбор» пустым.

Действие на спящем ноутбуке не проверено (только создание запроса).
- Отбор частями: `/api/event/<id>?part=&size=&filter=&hide=` (части по `REVIEW_PART_SIZE`=150, группы не режутся, фильтры до разбивки), в UI «Часть N из M», выбор размера, просмотр переходит между частями.
- Анализ порциями: выбор порции (`ANALYZE_PART_CHOICES`), `analyze.py --limit`, счётчик «осталось проанализировать», галочка «подряд до конца» (`_job_worker(auto=True)`, защита от зацикливания), после остановки — `--score-only` по обработанному.
- `make_groups` без матрицы N×N (окно по времени, `searchsorted`).
- Тесты: порции 10+10+10 и авто-режим на 30 фото, событие из 6 415 кадров (DOM ~2 700 узлов вместо 6 000+, часть ≈ 55 КБ вместо 2,8 МБ). Проверка «реальная БД не менялась» во время работы приложения пользователя невозможна — база меняется.

## Хронология доработок

1. Этап 1 — сканирование, события, серии, SQLite.
2. Этап 2 — оценка кадров; затем правки: clip_emotion считается при подсчёте баллов (применяется через `--score-only`), вес эмоций без лиц, негативные фразы, порог пересвета, YuNet для лиц, одинаковая оценка кадров группы.
3. Этап 3 — интерфейс отбора, решения в БД, экспорт.
4. Шаги 1–6: единая функция «Отобрать», S/M/L, pyiqa и разнообразие, обучение на выборе, работа без консоли, `BestShots.exe`.
5. Панель «Папки», экспорт по годам, подсказки на кнопках.
6. Вкладка «Дубли» (карантин `_Дубли`, журнал, возврат).
7. Большие архивы: части в «Отборе», порции анализа, защита от Modern Standby.

## Известные ограничения и важные замечания

- Метки кадров, которых пользователь не трогал, — это рекомендация системы (`train.py --seed-labels`), модель отчасти учится на собственных предложениях. Выигрыш личной модели небольшой и может быть случайным.
- Резкость и pyiqa считаются по превью 512 px; небольшая нерезкость на полном размере может не определиться.
- Отметка «проверено» привязана к номеру события; при пересчёте событий после добавления файлов номера могут сдвинуться.
- Видео на этапе 2 не оцениваются (дата — из имени или mtime, разрешение не определяется).
- Первый запуск на новой машине скачивает ~3 ГБ моделей (нужен интернет); дальше офлайн.
- Окно pywebview в итоговой проверке подтверждено по заголовку и процессам; UI кликался в панели браузера на том же сервере.
- Запомнить при тестах: `review.py` не стартует, если порт занят (раньше на Windows два сервера могли делить порт); не запускать тесты на порту 8765 рядом с рабочей копией — использовать другой порт и копию БД.
- Инцидент на шаге 1: тестовые запросы попали в рабочий сервер пользователя (порт 8765). Запись `decisions` по DSC_0001 удалена (89 решений пользователя сверены с резервной копией и целы), экспорт ничего не копировал, сервер пользователя был остановлен — его нужно перезапустить.
- `bestshots.db` — рабочая база пользователя и она растёт (на 2026-10-23: 1293 файла в Photo-samples с подпапками, 78 событий, 438 решений, 1277 меток; в `Export` есть прежние экспорты в раскладке «год\событие»). Решения не терять и не менять; тесты — только на копиях БД.
- Для тестов: переменная окружения `BESTSHOTS_SETTINGS` подменяет `settings.json` (иначе тесты через API перезаписывают настройки пользователя: `root`, `ui`); сервер для тестов — на другом порту и с `--db` копии; `/api/roots/set` и `/api/ui-state` пишут в settings.json.
- Известная особенность: «Исключить из анализа» удаляет строки из `files`, возврат папки «в анализ» не восстанавливает их — они появятся при следующем «Анализировать».
